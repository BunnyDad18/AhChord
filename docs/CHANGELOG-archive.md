## [0.3.0] - 2026-10-01

### Added
- 2026-10-01 — **Transpose + key change replace capo (ST-39 E1/E2):** the song page's display-only "Capo" control becomes a **Transpose** stepper (− / value / +, **-12…+12** semitones) plus a **"play in key"** dropdown that sets the transpose from the stored key. The active setting is shown in the header badge (`key G · playing in A (+3)`), and the player keeps its ± keyboard shortcuts over the new range. `GET /api/songs/{id}?capo=N` now accepts -12…+12; the stored chart is never mutated.
- 2026-10-01 — **Chord display modes on the song page (ST-39 F3):** an Inline/Above toggle — *inline* keeps chords in the text flow, *above* renders each chord on its own row directly over the syllable it belongs to (from the ChordPro character positions). The choice is persisted per browser.
- 2026-10-01 — **Lyrics font size controls (ST-39 F2):** A− / A+ buttons scale the song-page lyrics (0.8×–1.6×), persisted per browser.
- 2026-10-01 — **Multi-column songs on wide screens (ST-39 F1):** at ≥1400px the song page uses the full window width and long charts flow into 2–3 columns; lines never split across columns and section labels stay with their first line.
- 2026-10-01 — **Bug reports carry context (ST-39 D1):** every in-app bug report automatically appends where it came from — the page path, plus the song title/artist when reported from the player.
- 2026-10-01 — **Bug status pills + resolved-in version (ST-39 D2):** the Settings → Bug reports list shows a status pill per report (*new* / *resolved* / *waiting for a question*) with a status select; marking one resolved records the app version it was fixed in (`<!-- status: resolved in 0.3.0 -->` marker — legacy `<!-- resolved -->` markers still parse). New endpoint `POST /api/bug-reports/{id}/status` replaces the old resolve toggle; dates render smaller.

### Changed
- 2026-10-01 — **Import page rework (ST-39 A1/A2):** the Raw/Preview toggle now applies at every width (no more side-by-side panes), metadata fields flow into 2–3 columns, and the Import button moved to the top of the form. Importing no longer replaces the page with a success screen — a toast confirms it and the form clears for the next song.
- 2026-10-01 — **Wider queue cards + lifecycle ordering (ST-39 B1/B2):** the conversion queue column widens so pill, time and actions fit on one line per card; the list now orders processing → queued → converted → imported (failed last).
- 2026-10-01 — **Songs-list total count (ST-39 C1):** with no filter active the bottom of the list shows the library total (`Load more (12 of 40 songs)` / `40 songs`); `GET /api/songs/facets` gains a `total`.
- 2026-10-01 — **Consistent button sizing (ST-39 C2):** the queue's Live preview button now matches the Review/Retry buttons; all action buttons use the standard scale.
- 2026-10-01 — **Single lifecycle pill on queue cards (ST-38 Q1):** the conversion queue card now shows ONE status pill that walks the full lifecycle — QUEUED → PROCESSING → CONVERTED → IMPORTED (plus FAILED) — replacing the old chip plus separate "In library" badge. The Review button disappears once a song has been imported; imported rows keep only the remove action.
- 2026-10-01 — **File upload as its own tab with drag & drop (ST-38 Q2):** ChordPro file upload moves out of the Paste tab into a dedicated third "Upload file" tab on the import screen, accepting `.cho`/`.txt` via click-to-browse or drag-and-drop. Loading a file puts its content in the editor and switches to the Paste tab for review/import.

### Fixed
- 2026-09-30 — **Patch version resets on a minor bump:** the patch component is now derived from the commit count *since this prefix's release tag* (`v$(VersionPrefix)`) instead of the total commit count, so `0.2.x` starts at `0.2.0`. The 0.2.0 release commit is tagged `v0.2`; future bumps (e.g. to 0.3) should be tagged `v0.3` the same way.

## [0.2.0] - 2026-09-30

### Added
- 2026-09-30 — **Bug-report list in Settings (ST-37 D1):** a new "Bug reports" tab (visible to everyone) lists every bug submitted via the in-app button — timestamp, reporter and text from `/data/bug_reports.md` — with a resolved status and Mark resolved / Reopen buttons. New endpoints: `GET /api/bug-reports` (parses the file, newest first) and `POST /api/bug-reports/{id}/resolve`; resolution is persisted as an HTML-comment marker in the Markdown so it's visible from the host too.
- 2026-09-30 — **ChordPro file upload (ST-37 B1):** the import screen's paste tab accepts `.cho` / `.txt` files via a new "Upload .cho / .txt" button — read client-side straight into the editor, no upload endpoint needed.
- 2026-09-30 — **Queue cards show the song name at queue time (ST-37 A1):** adding a conversion now runs a plain string search over the input to find the title — HTML gets its `<title>` tag pulled and site suffixes stripped; pasted text is scanned line-by-line for a title-like candidate (skipping nav junk like "tab"). URL-only conversions fetch the page best-effort. Stored in a new `ImportDraft.InputPreview` column (`AddDraftInputPreview` migration); older drafts fall back to searching their stored input at list time.
- 2026-09-30 — **Metadata auto-review (ST-35 F3):** a background job (`MetadataReviewJob`, serial, LLM-driven via `docs/prompts/metadata-review.md`) works through the library and stores per-field proposals (title/artist/genre/year/key/tempo) on new `MetadataProposal` rows. Songs with pending proposals get a **Review (N)** button on their list row opening an inline panel with each change (`field: current → proposed`) and per-change Accept/Reject; accepting applies the value to the song. New songs are scanned automatically after import, and **“🔍 Scan metadata”** in the Songs header triggers a full-library rescan (`POST /api/songs/metadata-review`). `Song` gains a nullable `Tempo` (BPM) column (`AddSongTempoAndMetadataProposals` migration).
- 2026-09-30 — **In-app bug report button (ST-35 H2):** a 🐞 button in the header opens a dialog for bug notes; submissions append to `/data/bug_reports.md` on a new persistent volume (`ahchord_data`, mounted at `/data` in the app container) — readable from the host and ready to feed to OpenChamber. Each entry records timestamp (UTC) + reporter name + text via `POST /api/bug-reports`.
- 2026-09-30 — **Conversion status indicator in the header (ST-35 H1):** a new pill in the top bar appears whenever the conversion queue has activity — pulsing 🔄 while anything is queued/running, and ✓ with a count badge for converted songs not yet imported. Clicking it opens the import screen. The queue load + SignalR subscription moved from the Import page into the app shell, so the indicator (and finish/fail toasts) work on every page.
- 2026-09-30 — **Raw/preview toggle on the import screen (ST-35 G1):** on narrow screens (<900px) the Paste ChordPro section now shows *either* the raw text *or* the rendered preview, switched with a Raw/Preview tab; wide screens keep both panes side by side.
- 2026-09-30 — **Genre + year filled by the LLM during conversion (ST-35 F2):** the UG→ChordPro prompt now emits `{genre: ...}` (only when the page states one — no more guessed "folk" in `{tag:}`) and a `{year: YYYY}` directive. The parser captures both into `Header.Genre`/`Header.Year`, and import stores them on the song (`body > header` precedence, out-of-range years dropped). Both paste-import and UG draft-save accept optional `genre`/`year` overrides.
- 2026-09-30 — **Multiple versions of the same song (ST-35 F1):** importing a duplicate title+artist is now just another version (it already wasn't blocked). The Songs list shows **one row per song** with a **×N** count badge when more than one version exists (`GET /api/songs?grouped=true` — groups paginate, filters apply before grouping); clicking the row plays the **latest** version directly. New `GET /api/songs/{id}/versions` powers an "Other versions" section on the song page so older imports stay reachable. Row actions (Edit / + Playlist… / delete) act on the latest version; deleting one of several refetches to keep counts correct.
- 2026-09-30 — **Retry button for failed conversions (ST-35 E2):** failed queue rows now have a **Retry** button that re-enqueues the conversion (`POST /api/import/ug/{id}/retry` → 202; non-failed drafts get a 409). The row flips back to "queued" locally and follows the live progress as before.
- 2026-09-30 — **"Imported" tag on queue rows (ST-35 E3):** a succeeded draft that has been imported into the library now shows an "Imported" badge (success-colored pill) next to its status chip, so you can tell at a glance which conversions are done.
- 2026-09-30 — **Library-match tag on queue rows (ST-35 E4):** a succeeded draft whose converted title+artist already exists in the library gets an "In library" badge (duplicate signal, ties into F1). Computed per list fetch from `GET /api/import/ug` (`matchesLibrary`); hidden once the draft has been imported.
- 2026-09-30 — **Extracted names in the conversion queue (ST-35 E1):** when a UG→ChordPro conversion succeeds, the title/artist from its ChordPro header are stored on the draft (`AddDraftExtractedNames` migration) and shown on the queue row ("Title — Artist") instead of the raw first-line preview. The list API now returns `extractedTitle` / `extractedArtist`.
- 2026-09-30 — **Artist filtering (ST-35 D5):** the songs-list filter panel gains an **Artist** dropdown (distinct artists from `GET /api/songs/facets`, now `{artists, genres, decades}`) backed by a new `?artist=` parameter on `GET /api/songs` — pick an artist to see all their songs.
- 2026-09-30 — **Songs filter panel + genre field (ST-35 D4):** the Songs list now has a right-hand filter panel with **Genre** and **Decade** dropdowns (plus Clear filters); on narrow screens it moves above the list. Backing this: a new nullable `genre` column on songs (migration `AddSongGenre`, exposed in all song DTOs + create/update), `GET /api/songs?genre=&decade=` filtering, and `GET /api/songs/facets` returning the distinct genres/decades for the dropdowns. Artist filtering rides on this panel next (D5).
- 2026-09-30 — **Username-or-email login (ST-35 A1):** registration now takes a required unique **username** (3–32 chars of letters/numbers/`._-`, stored in Identity's uniquely-indexed `UserName`) alongside the email, and the login form is a single "Username or email" field — the server looks up by username first, then email. The user menu and Settings → Account now show the username (with the email), and `/api/auth/*` responses include it. Legacy accounts keep working: their username is their existing email.
- 2026-09-30 — **Agent test access (ST-35 A3):** setting `TEST_USER_PASSWORD` in `.env` now seeds a fixed `agent` account (`agent@ahchord.local`, display name "Agent") at startup, so the agent can log into the devnet deployment and test unattended. Idempotent — skipped if the user already exists; deployments that leave the variable unset get no extra account. (Uses the DI-registered `UserManager` because .NET 10 removed the concrete `UserStore<T>`.)
- 2026-09-30 — **UX polish & bug batch queued + clarified (ST-35):** new `docs/tasks/ST-35.md` capturing user-reported items across auth (username-or-email login via a new unique Username field, 30-day sessions, seeded test user for agent access), branding (full SelfHostedMusic → AhChord rename incl. DB/containers/solution, login screen cleanup), home page rework (multi-column Songs/Collections/Playlists layout with recent + counts, shuffle icon replacing the dice), songs list (clickable rows, bin icons, simpler delete confirm, genre + decade filter panel with a new release-year field), conversion queue (extracted names, retry, imported/match tags), metadata model (multiple song versions playing latest by default, genre/year fields, auto-review proposals for all derivable metadata) and header (conversion status indicator, in-app bug reporting to `/data/bug_reports.md`). All open questions answered; ready to implement.
- 2026-09-29 — **Songs library tab (ST-34):** new top-level **Songs** page (`/songs`, nav bar between Home and Playlists) listing every song in the library with a debounced title/artist search, key/capo badges, and "Load more" pagination. Each row has per-song actions: **▶ Play** (fullscreen player), **Edit**, **+ Playlist…** dropdown (adds to any playlist, shown grouped by collection; duplicates surface the server's 409 message), and **Delete** with the typed-title confirmation dialog. No backend changes — reuses `GET /api/songs`, `DELETE /api/songs/{id}` and `POST /api/playlists/{id}/songs`.
- 2026-09-29 — **Import queue + live LLM progress (ST-33):** the Import screen now has a persistent **conversion queue** above the tabs. "Convert in app" is now **"Add to conversion queue"** — it enqueues and returns instantly, so you can paste songs back-to-back without waiting. Each row shows a live status chip (queued/running/succeeded/failed), elapsed time, char count and retry indicator; running rows have an expandable **live preview** that streams the LLM's output token-by-token with a **raw-text / rendered-ChordPro toggle**; succeeded rows get a **Review** button (loads the ChordPro into the Paste tab for import) and queued rows can be **Cancelled**. Conversions run strictly one at a time (serial FIFO queue). New endpoints: `GET /api/import/ug` (your drafts, newest first) and `DELETE /api/import/ug/{id}` (cancel queued / remove finished; running → 409). The LLM call now streams (`stream: true`, SSE) and the job pushes per-user SignalR events (`ugDraftProgress` + `ugDraftChunk`) over the existing session hub, so every open tab stays in sync — replacing the old single-draft 2 s poll.
- 2026-09-25 — Initial changelog.
- 2026-09-29 — **LLM settings in-app (ST-30):** the UG→ChordPro LLM is now configured from Settings → LLM conversion instead of `.env` + restart. Admins set a band-wide default; any member can add a personal override that wins for their own conversions (`.env` remains the last-resort fallback). New "LLM conversion" settings section with effective-config readout + source badge, per-form **Test connection** (pings `GET {base}/models`, shows the model list), and masked API keys. First registered account is admin (`is_admin` JWT claim; oldest user promoted on existing installs). New endpoints: `GET/PUT /api/settings/llm[/mine|/global]`, `POST /api/settings/llm/test`. The Model field offers the server's model list as clickable chips (auto-fetched when Settings opens if a URL is saved, refreshed by Test connection) plus free-text fallback; a saved model the server no longer lists is cleared from the field on open. Compose maps `host.docker.internal` → host gateway so a local LM Studio can be used (`http://host.docker.internal:1234`) — the LLM server must listen on all interfaces, not just loopback. Base URLs are normalized everywhere: `/v1` is appended automatically when missing (for both conversions and Test connection), so `http://host:1234` and `http://host:1234/v1` work interchangeably.
- 2026-09-29 — **Version + changelog viewer (ST-31):** Settings now has an **About** section showing the app version and the rendered change log. New anonymous endpoint `GET /api/info` returns `{ service, version, changelog }`; the version comes from a new `<Version>0.1.0</Version>` in `WebApi.csproj` (single source of truth; both `/api/info` and `/api/health` now report the clean `0.1.0`, replacing the old `1.0.0.0`). The Dockerfile ships `CHANGELOG.md` into the image and the API serves it (container path with a dev walk-up fallback, mirroring the UG prompt file). Frontend renders the changelog as Markdown via `react-markdown`.
